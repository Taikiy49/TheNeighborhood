# THE NEIGHBORHOOD
## Master Roblox Game Build Prompt

You are the lead Roblox game engineer, systems designer, UI/UX designer, technical artist, and gameplay designer for a new multiplayer Roblox experience called:

# THE NEIGHBORHOOD

Your job is not merely to generate scripts.

Your job is to help me build a genuinely polished, commercially viable Roblox game that feels intentionally designed, visually cohesive, social, funny, replayable, and extremely easy to understand.

Use Roblox Studio and the Roblox Studio MCP tools available to you whenever possible. Inspect the existing project before making changes. Test what you build in Studio rather than assuming it works.

Use current Roblox/Luau best practices.

Keep the architecture modular and maintainable.

Do NOT dump the entire game into several enormous scripts.

Do NOT install random free models containing scripts.

Do NOT blindly generate hundreds of assets before the core gameplay is fun.

Build incrementally, test continuously, and preserve working functionality.

---

# 1. THE CONCEPT

The Neighborhood is a persistent multiplayer suburban social sandbox.

Imagine the social storytelling of The Sims combined with neighborhood rivalry, lighthearted crime, investigation, collecting, decorating, trading, progression, and Roblox-style chaos.

Every player owns a house.

Players live alongside other players in a colorful suburban neighborhood.

The neighborhood should feel peaceful at first glance.

Underneath that peaceful appearance, everyone is constantly scheming.

Players can:

- own houses
- decorate houses
- earn money
- collect rare possessions
- visit neighbors
- make friends
- trade
- prank neighbors
- spy on neighbors
- improve home security
- break into houses
- steal items
- investigate crimes
- discover evidence
- sell stolen goods
- recover stolen possessions
- place bounties
- acquire vehicles
- collect pets
- flex rare items
- participate in neighborhood events

The fundamental fantasy is:

> "I live in a neighborhood with real people, and I never know what ridiculous thing they're going to do next."

The game should generate STORIES.

Players should naturally end up saying things like:

"WHO STOLE MY GOLDEN TOILET?"

"Why is my couch in your house?"

"I literally have security footage of you."

"THAT IS NOT ME."

"Then why were your shoes outside my window?"

"Bro planted evidence on me."

"Someone stole my car while I was robbing somebody else's house."

These moments are the product.

---

# 2. THE CORE DESIGN PRINCIPLE

The game should create:

CURIOSITY → MISCHIEF → CONSEQUENCE → STORY → PROGRESSION → RETURN

Every system should reinforce this loop.

Players should constantly wonder:

"What happened?"

"Who did this?"

"What's inside that house?"

"How did they get that?"

"Can I steal that?"

"Can I afford that?"

"Can I trust this person?"

"How do I protect my stuff?"

"What happened while I was gone?"

The game should be understandable within approximately 30 seconds of joining.

Avoid complicated tutorials.

Teach through interaction, UI prompts, environmental design, and small contextual hints.

---

# 3. TARGET FEEL

The game should NOT feel like:

- a generic simulator
- a generic tycoon
- a copy-pasted Roblox experience
- an asset-store map
- a giant collection of unrelated mechanics
- an overly realistic crime simulator
- a dark or disturbing experience

Crime is deliberately cartoonish.

Think:

Home Alone.

Saturday morning cartoon.

The Sims.

Roblox chaos.

Neighborhood drama.

The tone should be mischievous, colorful, absurd, and funny.

A stolen Golden Toilet should be more memorable than stealing $50.

---

# 4. VISUAL DIRECTION

Create a cohesive visual identity.

Target aesthetic:

ROBLOX × THE SIMS × COZY SUBURBAN DIORAMA × CARTOON MISCHIEF

The neighborhood should look attractive enough that screenshots are immediately recognizable.

Use:

- stylized proportions
- warm suburban environments
- slightly exaggerated architecture
- clean silhouettes
- readable colors
- landscaped yards
- sidewalks
- street lamps
- mailboxes
- driveways
- trees
- fences
- small parks
- neighborhood signage
- visually distinct houses
- attractive day/night lighting

Avoid excessive realism.

Avoid visual clutter.

Avoid random asset styles.

Everything should feel like it belongs to the same game.

I care A LOT about UI quality.

Do NOT create default-looking Roblox UI.

Do NOT make the experience look AI-generated.

Avoid:

- random gradients
- excessive borders
- enormous text
- inconsistent padding
- arbitrary colors
- dozens of button styles

# 9. ROBBERY SYSTEM

This is one of the signature mechanics.

Robbery should NOT simply be:

hold E → receive money.

A robbery should feel like a tiny heist.

Example flow:

1. Choose target.
2. Observe house.
3. Identify security.
4. Select entry point.
5. Use appropriate tool.
6. Enter.
7. Search for valuables.
8. Decide what to steal.
9. Escape without detection.
10. Deal with evidence.
11. Sell, hide, trade, or display stolen item.

Different entry points might include:

- front door
- back door
- garage
- window

Different security:

- basic lock
- reinforced lock
- alarm
- camera
- motion detector
- guard dog
- smart lock

Different tools:

- lockpick
- glass cutter
- jammer
- disguise
- fake delivery package
- smoke device
- gloves

Balance these carefully.

There must always be counterplay.

Avoid creating pure pay-to-win advantages.

# 50. SERVER AUTHORITY

SECURITY IS IMPORTANT.

The client must never be trusted for:

- currency
- item ownership
- purchases
- robbery results
- inventory changes
- rare-item generation
- trade completion
- evidence creation
- rewards
- security-system results

The server should validate meaningful state changes.

Treat client requests as REQUESTS, not truth.

Example:

BAD:

Client:
"I stole the Golden Toilet. Give me $8,400."

GOOD:

Client:
"I attempted to interact with item X."

Server verifies:

- player position
- item exists
- item is stealable
- player has permission/tool
- house state
- cooldown
- interaction state

Then server performs the action.

# 64. SCREENSHOT-DRIVEN ITERATION

When Roblox Studio MCP provides screenshot or visual inspection capability, use it.

After implementing visual work:

1. Enter Play mode.
2. Navigate to the feature.
3. Capture/inspect the rendered result.
4. Evaluate composition, spacing, readability, lighting, scale, hierarchy, and polish.
5. Fix obvious problems.
6. Test again.
7. Repeat until the feature looks intentionally designed.

# 72. GRIEFING PREVENTION

Because players can mess with one another, grief prevention is essential.

The difference between:

FUN:

"Someone stole my ridiculous toilet and now I have a mystery."

and

NOT FUN:

"I logged in and everything I've spent 40 hours earning is gone."

must remain clear.

Design limits.

Possible safeguards:

- protected inventory
- limited theft frequency
- item recovery paths
- temporary protection after being robbed
- beginner protection
- protected premium purchases
- cooldowns
- victim compensation where appropriate
- vulnerable display slots
- insurance mechanics later

Monitor player behavior.

If a mechanic disproportionately causes players to quit, change it.

# 73. NEW PLAYER PROTECTION

- first-session robbery immunity
- starter-house security
- low-value beginner possessions
- gradually introduced PvP/social-risk systems

Do not create obvious "new player = free loot" incentives.

# 82. ERROR HANDLING

Use a safe fallback.

If a server system throws:

Log enough context to debug it.

Do not spam output continuously.

# 84. TESTING STRATEGY

EDGE CASES

What if the datastore fails?

What if the player has high latency?

EXPLOIT CASES

What if the client lies?

What if interaction requests are spammed?

What if invalid IDs are submitted?

What if the player teleports locally?

# 86. DISCONNECT BEHAVIOR

Define behavior explicitly.

Example:

Before reaching safe state:

Thief disconnects.

Potential approach:

Server resolves carried stolen property according to robbery state.

Likewise:

Victim disconnecting should not magically duplicate/delete items.

Design deterministic resolution rules.

# 87. DUPLICATION PREVENTION

Rare-item duplication would destroy the economy.

Every persistent item should have authoritative ownership.

Transfers should behave transactionally where possible.

During transfer:

OLD OWNER

→ pending transfer

→ validation

→ NEW OWNER

Avoid situations where both profiles save themselves as owner.

Design and test this carefully before creating highly valuable serialized collectibles.

# 88. EXPLOIT RESISTANCE

- inspect LocalScripts

- alter local UI
- spam requests
- fabricate parameters

- create items
- assign ownership
- complete arbitrary robberies
- bypass trades
- generate evidence
- award themselves collectibles

Server authority is mandatory.

Prefer:

# 210. MAP DESIGN FOR ENCOUNTERS

Do not create enormous roads separating everyone.

Centralize useful services.

Give players multiple routes while preserving encounter probability.

Important:

Not a giant open-world city.

Backyards are valuable gameplay spaces.

Potential:

- fences
- gates
- sheds
- collectible displays
- pets
- hiding routes
- garden decorations
- shortcuts

# 212. WINDOWS

Windows are important visually and mechanically.

Players can potentially:

- see valuables
- notice activity
- observe neighbors

Do not create invasive or inappropriate mechanics.

This is fictional in-game observation.

Windows should create temptation.

---

# 213. INTERIOR DESIGN

Interiors should be compact.

Do not make enormous empty Roblox rooms.

Furniture should create believable scale.

Navigation should remain easy.

A player should be able to understand the house layout quickly during a robbery.

---

# 214. DIFFERENT HOUSE LAYOUTS

Eventually introduce several layouts.

Different layouts create uncertainty.

But for MVP:

Use a small number.

Consistency accelerates development and testing.

# 215. SAFE ROOM — FUTURE

Potential expensive security upgrade:

Safe room / vault.

Players can protect limited high-value items.

Tradeoff:

Vaulted items provide security.

This creates an interesting choice:

Do I FLEX the Golden Toilet?

or

Do I protect it?

Excellent social tension.

# 216. DISPLAY BONUS

Displaying valuable possessions should provide social/status value.

- Collection Score
- visitor reactions
- neighborhood recognition
- achievements

This creates a meaningful choice:

DISPLAY IT → status, but other players can see what you own.

That tension is central to THE NEIGHBORHOOD.

# 232. ITERATION AFTER RELEASE

Do not immediately respond to low numbers by adding massive amounts of content.

Determine WHERE players leave.

Example:

Players leave before receiving house.

→ onboarding problem.

Players receive house but never interact.

→ world/UX problem.

Players buy items but never steal.

→ robbery discovery problem.

Players steal once and stop.

→ robbery depth/reward problem.

Victims quit after being robbed.

→ fairness problem.

Players love stealing but ignore investigation.

→ investigation isn't fun enough.

Fix the bottleneck.
